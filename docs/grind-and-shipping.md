# نوع آسیاب و روش دریافت سفارش

## تکمیل ۲۰۲۶-۱۱-۰۵: دستگاه آسیاب

- انتخاب «آسیاب‌شده» چهار دستگاه بدون پیش‌فرض نشان می‌دهد: موکاپات، اسپرسوساز خانگی، نیمه‌صنعتی و صنعتی. افزودن به سبد بدون انتخاب دستگاه ممکن نیست. با انتخاب دانهٔ کامل، دستگاه پاک می‌شود؛ هزینهٔ کالا تغییری نمی‌کند.
- ردیف سبد بر اساس SKU، نوع آسیاب و دستگاه شناسایی می‌شود. تغییر دستگاه در سبد فقط با ردیف کاملاً مشابه ادغام می‌شود. کلید localStorage قبلی باقی است و سبدهای قدیمی بدون حذف، برای تکمیل انتخاب نمایش داده می‌شوند.
- `CartItem.grindDevice` و `OrderItem.grindDevice` از enum جدید `GrindDevice` هستند. مقدار سفارش snapshot است؛ سفارش تاریخی دستگاه ساختگی نمی‌گیرد و برای آسیاب‌شدهٔ قدیمی «دستگاه ثبت نشده» نمایش داده می‌شود.
- اعتبارسنجی سرور دستگاه را برای آسیاب‌شده الزام و برای دانهٔ کامل رد می‌کند. دستگاه وارد هش تأیید سفارش شده و در تأیید، تاریخچه و جزئیات مشتری/مدیر دیده می‌شود.
- روش‌های سفارش جدید فقط پست، تیپاکس و پیک‌اند. PICKUP فقط برای نمایش تاریخچه حفظ شده؛ اگر آخرین روش کاربر PICKUP بوده باشد، فرم سفارش جدید بدون پیش‌فرض باز می‌شود.
- نشان هدر A کرم‌رنگ داخل مربع زرشکی با عبارت کوچک coffee roastery است؛ ظاهر فارسی RTL سایت حفظ می‌شود.

### migration و راه‌اندازی

فایل `prisma/migrations/20261105000000_grind_device/migration.sql` دو ستون اختیاری، enum و ایندکس‌های یکتایی متناسب با دستگاه را اضافه می‌کند. ایندکس جزئیِ حالت بدون دستگاه و ایندکس قدیمیِ نوع آسیاب نامشخص، تکرار ردیف‌ها را می‌بندند. CHECK دیتابیس اجازهٔ دستگاه برای دانهٔ کامل را نمی‌دهد. داده‌ها، شناسه‌ها و قیمت‌های موجود بازنویسی نمی‌شوند؛ PICKUP از enum دیتابیس حذف نمی‌شود.

وضعیت فعلی: **اعمال‌شده در ۲۰۲۶-۱۱-۰۵ با اجازهٔ صریح کاربر برای همین migration**. دستور `npm run db:deploy` موفق بود. بررسی فقط‌خواندنی با اتصال واقعی `getDb` ثبت migration، دو ستون جدید، سه ایندکس سبد (شامل ایندکس قدیمی نوع آسیاب نامشخص)، دو CHECK و چهار مقدار enum را تأیید کرد؛ خواندن `grindDevice` از CartItem و OrderItem نیز موفق بود. رکورد آزمایشی در دیتابیس اصلی ایجاد نشد. پس از دریافت تغییرات، سرور محلی را یک بار مجدداً اجرا کن.

1. با TEST_DATABASE_URL و TEST_DIRECT_URL متعلق به یک branch مجزای Neon، `npm run test:grind-migration` را اجرا کن. آزمون با اسکیمای موقت و rollback، حفظ رکوردها، ایندکس‌ها و قیدها را بررسی می‌کند؛ هرگز به دیتابیس اصلی fallback نمی‌کند.
2. برای آزمون کامل روی branch آزمایشی خالی، `npm run db:prepare:test` تمام migrationها و کاتالوگ آزمایشی را آماده می‌کند؛ سپس CHECKOUT_E2E=1 آزمون checkout واقعی را فعال می‌کند.
3. اجرای `npm run db:deploy` برای این migration روی دیتابیس فعلی با اجازهٔ کاربر انجام و بررسی شد. اگر استقرار دیگری دیتابیس جداگانه دارد، migration باید پیش از سرویس‌دهی نسخهٔ جدید روی همان مقصد اعمال شود.

### نتیجهٔ بررسی‌ها

۵۵ تست واحد، ۴ تست سرور (از جمله action واقعی سبد/سفارش با DB شبیه‌سازی‌شده)، ۴ تست مرورگر در موبایل و دسکتاپ، lint، typecheck و build بررسی شدند. همه موفق بودند؛ lint یک هشدار قدیمی در zarinpal.ts دارد. پیش‌نمایش هر دو تم بررسی شد و عرض ۳۲۰ پیکسل بدون تداخل هدر بود. تست migration به‌دلیل نبود تنظیمات آزمایشی skip شد و آزمون نوشتنی checkout واقعی اجرا نشد. هیچ کامیتی انجام نشده است.

## رفتار فروشگاه

- کنار وزن، مشتری باید «دانهٔ کامل (آسیاب‌نشده)» یا «آسیاب‌شده» را انتخاب کند. انتخاب روی قیمت اثر ندارد.
- یک SKU با دو نوع آسیاب، دو ردیف مستقل در سبد می‌سازد. تغییر تعداد یا حذف یکی، دیگری را تغییر نمی‌دهد. نوع آسیاب از داخل سبد نیز قابل تغییر است؛ انتخاب‌های یکسان با سقف تعداد فعلی سبد ادغام می‌شوند.
- سبدهای قدیمی مرورگر حفظ می‌شوند، ولی تا انتخاب نوع آسیاب قابل ثبت سفارش نیستند. سمت سرور نیز انتخاب خالی یا نامجاز رد می‌شود.
- در `/checkout/place-order` روش دریافت اجباری است: پست، تیپاکس، پیک یا تحویل حضوری. آخرین روش ثبت‌شده در سفارش‌های همان حساب پیشنهاد می‌شود و قابل تغییر است. برای حساب بدون سابقهٔ روش دریافت، گزینه خالی است.
- روش دریافت و نوع آسیاب در فهرست و جزئیات سفارش مشتری و مدیر دیده می‌شوند. سفارش‌های قدیمی «ثبت نشده» نشان می‌دهند؛ اطلاعات گذشته حدس زده یا بازنویسی نمی‌شوند.
- هزینهٔ ارسال همچنان تعیین‌نشده است؛ انتخاب روش ارسال در این مرحله تعرفه یا اتصال سرویس حمل ایجاد نمی‌کند. روند آدرس فعلی برای همهٔ روش‌ها حفظ شده است.
- هدر با «آ» بزرگ جایگزین نوشتهٔ انگلیسی شده و هر دو تم و موبایل بررسی شده‌اند.

## داده و اعتبارسنجی

- `Product.grindOptions`: گزینه‌های مجاز آماده‌سازی با پیش‌فرض هر دو حالت. محصولات موجود و جدید این پیش‌فرض را دارند؛ شناسه و قیمت SKU تغییر نمی‌کند.
- `CartItem.grind`: انتخاب مشتری. یکتایی سبد بر اساس سبد، SKU و نوع آسیاب است. ایندکس جزئی، یکتایی ردیف‌های قدیمیِ بدون انتخاب را هم حفظ می‌کند.
- `OrderItem.grind`: تصویر ثابت انتخاب هر قلم هنگام ثبت سفارش، مستقل از تغییر یا حذف محصول.
- `Order.shippingMethod`: روش ثبت‌شدهٔ همان سفارش. سفارش‌های قدیمی مقدار null دارند.
- `cartInputSchema` و `placeOrderSchema` انتخاب‌های معتبر را در سرور الزام می‌کنند. سرور سازگاری آسیاب با Product را دوباره بررسی می‌کند و مبلغ را از دیتابیس می‌خواند. تغییر نوع آسیاب، هش تأیید سفارش را تغییر می‌دهد؛ تأیید قدیمی پذیرفته نمی‌شود.
- تکرار درخواست با checkoutKey یکسان، همان سفارش را برمی‌گرداند و روش دریافت یا انتخاب‌های قبلی آن را بازنویسی نمی‌کند.

## اجرا و آزمون

migration `prisma/migrations/20261104000000_grind_and_shipping/migration.sql` در ۲۰۲۶-۱۱-۰۵ با اجازهٔ صریح کاربر روی دیتابیس فعلی از طریق `npm run db:deploy` اعمال شد. بررسی فقط‌خواندنی از اتصال واقعی برنامه، ثبت موفق migration، وجود هر چهار ستون و هر دو ایندکس سبد، و خواندن فیلدهای جدید محصول و سفارش با Prisma را تأیید کرد. رکورد آزمایشی یا سفارش واقعی ایجاد نشد. Prisma Client در مرحلهٔ پیاده‌سازی تولید شده است؛ اگر سرور محلی هنوز نسخهٔ قدیمی را نگه داشته، آن را دوباره راه‌اندازی کن. TEST_DATABASE_URL و TEST_DIRECT_URL هنوز تنظیم نیستند و تأیید آزمون کامل نوشتنی checkout روی branch آزمایشی باقی است.

- ۵۴ تست واحد موفق: سبد قدیمی، تفکیک آسیاب، اعتبارسنجی انتخاب و روش دریافت.
- سه تست `npm run test:order-options` موفق با دیتابیس شبیه‌سازی‌شده: محاسبه و snapshot، مالکیت و پیشنهاد ارسال قبلی، action واقعی سفارش با جلوگیری از تأیید قدیمی و ثبت تکراری.
- چهار تست مرورگر در موبایل/دسکتاپ موفق: انتخاب اجباری، نگه‌داری دو نوع در سبد، سازگاری سبد قدیمی، خرید اول/خرید بعدی و حفظ انتخاب در خطای شبکه. تصاویر هر دو تم بررسی شدند.
- schema، TypeScript و build موفق؛ lint فقط هشدار قبلی zarinpal.ts را دارد.
- تست نوشتنی روی دیتابیس اصلی اجرا نشده است. آزمون checkout واقعی برای grind و shippingMethod به‌روز شده، ولی اجرای آن و آزمون migration روی branch آزمایشی نیازمند تنظیمات TEST_DATABASE_URL و TEST_DIRECT_URL هستند.

هیچ کامیتی انجام نشده است.
