# OTP ثبت‌نام آ

ثبت‌نام به پیامک کاوه‌نگار وصل است. افزودن اولین شمارهٔ کاربران قدیمی در [مرحلهٔ ۱ شمارهٔ حساب](account-phone.md) پیاده شده و migration جدا دارد. ورود با ایمیل و رمز و بازیابی ایمیلی تغییر نمی‌کنند. ورود پیامکی، تغییر شمارهٔ تأییدشده و الزام شماره برای checkout هنوز پیاده نشده‌اند.

## راه‌اندازی

- SDK رسمی `kavenegar` نصب شده و ارسال با `VerifyLookup` انجام می‌شود.
- در پنل کاوه‌نگار یک الگوی تأییدشده با `%token` داشته باش، اعتبار پنل را بررسی کن و نام دقیق الگو را در `KAVENEGAR_OTP_TEMPLATE` بگذار. مثال متن: «آ — کد تأیید شما: %token».
- `KAVENEGAR_API_KEY`، `KAVENEGAR_OTP_TEMPLATE` و `OTP_SECRET` باید در محیط سرور تنظیم باشند. `OTP_SECRET` تصادفی و حداقل ۳۲ کاراکتر است؛ نمونهٔ محلی در `.env.local` تولید شده و مقدارش در خروجی چاپ نشده است. برای هاست، کلید را امن کپی کن؛ فایل محلی خودکار منتشر نمی‌شود.
- تغییر تنظیمات محلی نیازمند restart سرور است. پیش از انتشار این نسخه، migration `20261103000000_signup_otp` باید روی مقصد اعمال شده باشد: افزودن شماره و زمان تأیید به User و جدول SignupOtp، بدون حذف کاربران قبلی. تولید Prisma Client به‌تنهایی migration نیست.
- نبود تنظیمات یا شکست ارسال، ثبت‌نام را متوقف می‌کند؛ مسیر بدون OTP وجود ندارد. رمز و OTP را در چت یا گزارش خطا نفرست.

## رفتار

در `/register` نام، ایمیل، موبایل و رمز را وارد کن؛ «دریافت کد تأیید» را بزن و سپس کد شش‌رقمی را وارد کن. کد دو دقیقه اعتبار دارد. ارسال مجدد بدون فاصلهٔ اجباری، حداکثر ۲۰ بار در ساعت برای هر شماره و ایمیل ممکن است؛ سقف کل ارسال در پنجرهٔ ۲۴ساعته ۲۰۰ درخواست است. تلاش‌های ناموفق ارسال هم سهمیه مصرف می‌کنند تا قطع سرویس باعث درخواست‌های بی‌حد نشود.

شماره‌های ایران با ارقام فارسی/عربی و قالب `+98`/`0098` پذیرفته و با قالب `09xxxxxxxxx` ذخیره می‌شوند. چند ایمیل می‌توانند یک شماره داشته باشند؛ شماره unique نیست. پس از تأیید، شماره در User ذخیره می‌شود و مدیر آن را در `/admin/users` با وضعیت تأیید و لینک تماس می‌بیند. شمارهٔ گیرندهٔ سفارش مستقل باقی می‌ماند.

پیش از تأیید هیچ User ساخته نمی‌شود. challenge فقط هش HMAC کد را نگه می‌دارد؛ هش به ایمیل، شماره و شناسهٔ درخواست متصل است. پنج حدس غلط، انقضا یا مصرف قبلی آن را غیرقابل استفاده می‌کند. شمارش تلاش ناموفق commit می‌شود؛ مصرف کد و ساخت حساب تراکنشی و تحت قفل رکورد هستند. نقش حساب تازه همیشه CUSTOMER است.

SDK به HTTPS وصل می‌شود. برنامه پس از ده ثانیه انتظار، شکست را اعلام می‌کند؛ خود SDK امکان لغو درخواست را ارائه نمی‌کند. پاسخ دیرهنگام، challenge شکست‌خورده را فعال نمی‌کند و ارسال خودکار تکرار نمی‌شود. موفقیت API یعنی پذیرفته‌شدن ارسال، نه اثبات رسیدن پیامک به گوشی.

## آزمون و محدودیت تأیید

- `npm run test:unit`: اعتبارسنجی شماره/کد و اتصال هش به هویت و درخواست.
- `npm run test:signup`: SDK شبیه‌سازی‌شده؛ تست تراکنشی فقط با `TEST_DATABASE_URL` و `TEST_DIRECT_URL` روی branch آزمایشی اجرا می‌شود. در نبود تنظیمات تست، صریحاً skip می‌شود.
- `npx playwright test tests/helpers/forms.spec.ts --grep signup`: فرم واقعی با action شبیه‌سازی‌شده، موبایل، دسکتاپ، دو تم و حفظ ورودی هنگام خطا.
- هیچ‌کدام از این تست‌ها پیامک واقعی نمی‌فرستند. تست عملی ارسال و ثبت‌نام را صاحب پروژه با شمارهٔ خودش انجام می‌دهد.
