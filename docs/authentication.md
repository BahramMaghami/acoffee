# احراز هویت آ

## مسیرها و رفتار

- `/login`: ورود با ایمیل و رمز عبور.
- `/register`: ثبت‌نام و ورود خودکار با نقش `CUSTOMER`.
- `/account`: حساب محافظت‌شده با مشخصات واقعی دیتابیس و تاریخ عضویت شمسی.
- `/api/auth/[...nextauth]`: handlerهای NextAuth.

مهمان در هدر آیکن کاربر و «ورود/ثبت‌نام» می‌بیند. پس از ورود، حرف اول نام با منوی حساب و خروج جایگزین می‌شود. مرور فروشگاه و سبد مهمان عمومی است. ثبت سفارش و اتصال سبد به حساب هنوز مرحلهٔ بعد هستند.

## پیاده‌سازی

نسخهٔ نصب‌شده `next-auth@5.0.0-beta.32` است؛ این نسخهٔ پیش‌انتشار برای APIهای App Router استفاده شده است. تنها provider، Credentials است. تنظیمات در `auth.ts` و عملیات ثبت‌نام، ورود و خروج در `actions/user.actions.ts` هستند. راهنمای API: [Auth.js](https://authjs.dev/reference/nextjs).

نشست JWT رمزنگاری‌شده در کوکی HttpOnly با SameSite=Lax و اعتبار ۱۴ روز قرار دارد؛ در HTTPS کوکی Secure است. زمان تمدید نشست طبق رفتار NextAuth است. برای این روش، جدول OAuth یا Session و Prisma Adapter احراز هویت لازم نیست؛ کاربر مستقیماً با Prisma خوانده و نوشته می‌شود. نقش برای مجوز عملیات حساس باید با `requireUser` از دیتابیس دوباره خوانده شود، نه از مقدار ارسالی کلاینت یا نقش قدیمی JWT.

Zod هم سمت فرم با React Hook Form و هم داخل Server Action ورودی را بررسی می‌کند. ایمیل trim و lowercase می‌شود؛ رمز بدون trim با bcrypt و cost=12 هش می‌شود. حداقل رمز ثبت‌نام ۸ کاراکتر و سقف آن ۷۲ بایت UTF-8 است. ورودی کلاینت نمی‌تواند نقش مدیر یا شناسه تعیین کند. مسیر بازگشت فقط از فهرست مسیرهای داخلی مجاز پذیرفته می‌شود.

جدول `AuthRateLimit` شمارندهٔ اتمیک و مشترک بین نمونه‌های سرور دارد؛ برای هر ایمیل ۸ تلاش ورود در ۱۵ دقیقه و ۳ تلاش ثبت‌نام در یک ساعت مجاز است. کلید از hash ایمیل و نوع عملیات ساخته می‌شود. این محدودیت برای هر هویت است و محدودیت کلی IP نیست. ردیف منقضی در تلاش بعدی همان هویت بازنشانی می‌شود؛ برای پاک‌سازی دوره‌ای ردیف‌های قدیمی می‌توان `DELETE FROM "AuthRateLimit" WHERE "resetsAt" < CURRENT_TIMESTAMP` را در job دیتابیس اجرا کرد.

زمان در PostgreSQL میلادی می‌ماند؛ `lib/date.ts` نمایش هجری شمسی را با منطقهٔ `Asia/Tehran` انجام می‌دهد. هنوز فرم ورود تاریخ نداریم.

## راه‌اندازی

`DATABASE_URL` و `DIRECT_URL` باید مربوط به همان دیتابیس Neon باشند. `AUTH_SECRET` یک مقدار تصادفی خصوصی و ثابت است؛ نمونهٔ تنظیمات در `.env.example` قرار دارد. تغییر secret نشست‌های موجود را باطل می‌کند. برای استقرار، `AUTH_URL` را برابر دامنهٔ HTTPS برنامه قرار دهید.

```bash
npm install
npm run db:deploy
npm run dev
```

Migration `20260908000000_auth_rate_limit` جدول محدودکننده را اضافه می‌کند. رمز کاربران seed در فایل محلی و نادیده‌گرفته‌شدهٔ `.seed-users.local.json` است؛ هیچ رمز ثابتی در کد تعریف نشده است. ثبت آرگومان‌های Server Function در `next.config.ts` غیرفعال است تا رمز فرم‌ها در لاگ توسعه نوشته نشود.

## تست

```bash
npm run test:unit
npm run typecheck
npm run lint
npm run build
npm run test:ui
```

تست‌های عادی رابط به حساب آزمایشی یا نوشتن در Neon نیاز ندارند. تست واقعی را در PowerShell با تنظیم زیر اجرا کنید:

```powershell
$env:AUTH_E2E='1'
npx.cmd playwright test tests/ui/auth.spec.ts
```

این تست ثبت‌نام، صحت hash، نقش مشتری، نشست ۱۴روزه و ماندگاری آن، رد کوکی دستکاری‌شده، رمز اشتباه، محدودیت تلاش‌ها و بازنشانی بازهٔ منقضی، خروج و ورود کاربران seed را روی دسکتاپ و موبایل بررسی می‌کند. فقط کاربران تصادفی خود تست و شمارنده‌های مربوط به آن‌ها در پایان پاک می‌شوند. تست به فایل رمزهای seed نیاز دارد. Trace، ویدئو و اسکرین‌شات خودکار شکست برای تست احراز هویت خاموش‌اند؛ رمزها نباید در خروجی یا artifact منتشر شوند.
